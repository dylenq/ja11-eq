## Phase Boundary

Phase 4 turns the working `JA11EQ` executable into a double-clickable `JA11 EQ.app` built by one script, and adds a README. No new app behaviour. `JA11Kit`, `JA11EQCore`, the app sources, `ja11-probe` and `ja11-eq` are not changed, with one permitted exception in D-06.

</domain>

<decisions>
## Implementation Decisions

### Build script
- **D-01:** `scripts/make-app.sh` (bash, executable bit set) runs from any directory, builds the `JA11EQ` product in release configuration with `swift build -c release`, and assembles `dist/JA11 EQ.app`. It resolves the binary through `swift build -c release --show-bin-path`, never a hard-coded `.build` path. It exits non-zero with a clear message if any step fails (`set -euo pipefail`), and replaces only its own previous output at `dist/JA11 EQ.app`.
- **D-02:** Bundle layout: `Contents/MacOS/JA11 EQ` (the release binary, copied and renamed), `Contents/Info.plist`, `Contents/Resources/` (holds the icon if one is produced). No frameworks, no embedded helper tools.
- **D-03:** `Info.plist` keys: `CFBundleName` and `CFBundleDisplayName` = `JA11 EQ`; `CFBundleExecutable` = `JA11 EQ`; `CFBundleIdentifier` = `local.ja11.eq`; `CFBundlePackageType` = `APPL`; `CFBundleShortVersionString` = `1.0`; `CFBundleVersion` = `1`; `LSMinimumSystemVersion` = `14.0`; `NSHighResolutionCapable` = true; `NSPrincipalClass` = `NSApplication`; `LSApplicationCategoryType` = `public.app-category.music`. The plist must pass `plutil -lint`.
- **D-04:** The bundle is ad-hoc signed with `codesign --force --sign - "dist/JA11 EQ.app"` and must pass `codesign --verify --deep --strict`. No sandbox entitlement, no hardened runtime, no notarization, no Developer ID — local personal use only.
- **D-05:** `dist/` is added to `.gitignore`; build output is never committed.
- **D-06:** An app icon is optional. If one is added it is generated by the script itself from code (for example drawn with a small Swift or `sips`/`iconutil` step) — no binary image is committed and nothing is downloaded. If generating an icon is not straightforward, ship without one (the generic app icon) and say so in the summary. The existing activation-policy code in `JA11EQApp` is harmless in a bundle and stays; it may be touched only if the bundled app misbehaves because of it, and any such change is a recorded deviation.

### README
- **D-07:** `README.md` at the repo root, written for the owner of the dongle rather than a developer. Sections: what the app is (one paragraph); requirements (a JA11, macOS 14 or later, Xcode command-line tools for building); build and run (`scripts/make-app.sh`, then open `dist/JA11 EQ.app`, optionally drag it to Applications); using it (presets, editing bands, dragging handles, Option-drag for Q, Auto pre-gain, Apply and the roughly one-second audio dropout while the dongle saves, unsaved-changes label, Revert); safety (only the Custom/USER1 slot is ever written, factory presets cannot be changed, the original USER1 curve is backed up once to `~/Library/Application Support/JA11 EQ/user1-original.json`); restoring the original curve (Device → Restore Original…, or `ja11-eq restore`); permissions (if macOS refuses access, enable the app under System Settings → Privacy & Security → Input Monitoring); the command-line tools (`ja11-probe`, `ja11-eq` and their subcommands); troubleshooting (Not connected, Access refused, Apply reports a mismatch, no audible change); credits (protocol from the 0BSD `jeromeof/devicePEQ` project).
- **D-08:** Every command and path in the README must be real: taken from the code as built (`ja11-eq --help`, `ja11-probe --help`, the actual menu and button titles in `Sources/JA11EQ`), not from memory.

### Verification
- **D-09:** Automated checks: the script exits 0 from a clean `dist/`; the bundle exists with the D-02 layout; `plutil -lint` passes; `codesign --verify --deep --strict` passes; the bundled binary launched directly (`dist/JA11 EQ.app/Contents/MacOS/JA11 EQ`) is still running after 5 seconds and is then stopped; running the script a second time also exits 0; `swift test` still passes; `git status` shows `dist/` ignored.
- **D-10:** Human checks at the end of the phase: double-clicking `dist/JA11 EQ.app` in Finder opens the app (macOS may ask for confirmation the first time for an ad-hoc signed app — note in the README what to do); it connects to the JA11 and loads the curve; Apply works as it does in the development build; whether macOS asks for Input Monitoring for the double-clicked app, and if so that granting it works; following the README's restore steps puts the original USER1 back.

### Claude's Discretion
- Whether an icon is produced and how (within D-06)
- README wording and ordering within D-07
- Whether the script also prints a short "how to open it" line when it finishes

</decisions>

<specifics>
## Specific Ideas

- DEVICE SAFETY: executors may launch the bundled app (it reads the dongle on connect) but must NOT apply, restore or switch presets on the real dongle, and must not run `ja11-eq` commands that contact it. GUI writes from the packaged app are the human's checks.
- Foreground `sleep` is blocked in the harness; the launch check starts the bundled binary in the background, waits with a perl select, checks it with `kill -0`, then stops it. No app process is left running.

</specifics>
