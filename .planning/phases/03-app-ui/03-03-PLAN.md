Facts carried over, no rediscovery needed:

- An apply on the real dongle takes about 4 seconds, including the USB drop of about 0.9 s after the save (`02-DEVICE-LOG.md`). `JA11Device` refuses a write operation that starts while a read request is in flight as `.busy` (nothing sent) and, for a leading read during an apply, may end it as `.writeInterrupted` before any value frame; the app avoids both by waiting for the watch loop's read first.
- `JA11Device.watch()` reads the full state on every connect (`.connected`, then `.state` or `.readFailed`). After the save the dongle drops and returns, so the watch loop yields `.disconnected`, `.connected`, `.state` in the middle of an apply.
- `ApplyTests.makeDevice(on:)` builds a started, connected device with millisecond pauses and a 500 ms reconnect timeout. `ApplyTests.selectFrame(n)` is the pinned select-slot frame. `FakeDongle(afterSave: .dropsAndReturns(after:))`, `.dropsForGood`, `gainError:`, `ignoresWrites:`, `ignoresSelect:` and `slot:` exist. A normal apply sends nine write frames (pre-gain, count, five filters, save, select slot 3).
- A temporary-directory `BackupStore(fileURL:)` is the only backup store a test may use; nothing in a test may use `BackupStore.standard`.
- The real dongle holds the Phase 2 test curve in USER1 and a backup of the original is in `~/Library/Application Support/JA11 EQ/user1-original.json`. Automated steps here do not write to either.
