Command-line contract after this plan:

```text
usage: ja11-probe [--watch] [--raw]
  (no arguments)  read the JA11's preset slot, pre-gain and filters once and print them
  --watch         keep running; report disconnect and connect, and read again on each connect
  --raw           also print every frame sent and received as hex
  --help          show this text
exit status: 0 state printed, 1 no JA11 found, 2 usage error, 3 access refused by macOS, 4 read failed
```

stdout lines: `slot:`, `pre-gain:`, `filters:`, `filter N:` (state); `connected`, `disconnected`
(watch mode); `tx:`, `rx:`, `info:` (with `--raw`). All error text goes to stderr.
</interfaces>

Reply vectors for tests (each a frame; zero-pad to 20 bytes, and prepend 0x02 where a test asks
for the layout with a leading report-ID byte):

- slot 3: BB 0B 00 00 16 01 03 00 EE
- count N: BB 0B 00 00 18 01 NN 00 EE
- pre-gain -6.0: BB 0B 00 00 17 02 FF C4 00 EE; pre-gain +3.0: BB 0B 00 00 17 02 00 1E 00 EE
- filter 0, low shelf, 100 Hz, +6.0 dB, Q 0.70: BB 0B 00 00 15 08 00 00 3C 00 64 00 46 01 00 EE
- filter 1, peak, 1000 Hz, -6.0 dB, Q 1.41: BB 0B 00 00 15 08 01 FF C4 03 E8 00 8D 00 00 EE

Request forms (D-03): a responder can tell them apart by payload length — 20 bytes is the padded
form, 8 or 9 bytes the unpadded one — and can answer only one of them to exercise the fallback.

The stream first reports the link as it is when watching begins — when the device is already connected, the first elements are `.connected` and the outcome of a read — and then follows every transport event in order: on `.connected` yield `.connected`, run `readState()`, and yield `.state(state)` or `.readFailed(error)`; on `.disconnected` yield `.disconnected`; on `.openFailed(error)` yield `.openFailed(error)`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process → USB device | Output reports can change the DAC. Watch mode sends on every connect, so it multiplies whatever the read path sends. |
| USB device → process | Reply bytes, reply timing and the reported filter count are device-supplied. |
| command line → process | Arguments come from the user or a script. |
| macOS privacy controls → process | macOS decides whether the open is allowed; the probe reports that decision and does not influence it. |
