<objective>
Build everything the write path needs that can be proven without the dongle: the editable curve
model with clamping, SET-frame encoding, the replaced send gate, the apply sequence with read-back
comparison, the response math and auto pre-gain.

Purpose: Phase 2 is the first phase that writes to the user's only JA11. Nothing may be sent to it
until the encoder, the gate and the apply logic are tested byte for byte. This plan sends nothing
to the real dongle at all.

Output: `EQCurve.swift`, `EQResponse.swift`, SET builders and gate in `FiioFrame.swift`, the gate
swap in `HIDTransport.swift`, `JA11Device.apply(_:)`, an in-memory dongle for tests and four new
test suites.

Tracer note: the tracer task wires one curve through every layer this phase changes - model,
codec, gate, transport, device actor - and ends at the `ReportTransport` seam on an in-memory
dongle. The real dongle and the `ja11-eq` command are deliberately not part of it: no SET frame may
reach the hardware before plan 02-02 has finished the failure handling and the backup, and plan
02-04 owns first contact. The tracer touches seven files because each layer lives in its own file.

How D-01 is read: the filter payload is 8 bytes - index, gain (2), frequency (2), Q (2), type. The
`0x00` that D-01 lists after the type is the first byte of the `00 EE` terminator, as the reference
frame shows (`... 00 46 01 | 00 EE`, 16 bytes). The reference frame is what the tests pin.
</objective>

Each one first replaces NaN (gain and pre-gain: 0.0; Q and frequency: the lower bound of the range), then clamps to the matching `JA11Limits` range, then scales (gain and pre-gain by 10, Q by 100, frequency by 1) and rounds with `.toNearestOrAwayFromZero`, returning an `Int`. 2. `Sources/JA11Kit/Protocol/FiioFrame.swift` (D-01, D-02, D-04, D-11): add `setHeader` as the two bytes AA 0A. A private builder assembles header, 00 00, the write command's raw value, its `dataLength`, the data, the existing `terminator` (00 EE), then zero bytes up to `JA11.payloadLength`; SET frames exist only in this 20-byte form. `setPreGain` carries `JA11Limits.preGainTenths` as two bytes, high byte first, two's complement. `setFilterCount` carries one byte, the count clamped to 0...5. `setFilter` takes a `Band` and carries eight bytes: the index, `gainTenths` as two bytes two's complement, `hertz` as two bytes unsigned, `qHundredths` as two bytes unsigned, then `typeID`; it stops with a precondition failure for an index outside `0..<JA11Limits.maxBands` or a `typeID` above 2, the same way `readFilter(index:)` treats a bad index. `selectSlot` takes a `PresetSlot` and carries its raw value. `saveToUser1` takes no argument and always carries `JA11SlotID.user1`; there is no builder that takes a slot to save to (D-11). The builders are internal, not public.
   `isSetRequest` is true only for a payload of exactly 20 bytes that starts AA 0A 00 00, has a `JA11WriteCommand` raw value at byte 4 and exactly that command's `dataLength` at byte 5, has 00 EE straight after the data and nothing but zero bytes after that, and whose data passes the command's rule: save - the byte is 3; preset slot - the byte is 0...4; filter count - the byte is 0...5; pre-gain - the signed value is within -120...120; filter - index 0...4, signed gain within -120...120, frequency within 20...20000, Q within 10...1000, type 0...2. The byte before EE must be 00: D-04 fixes that position for write frames, and the gate is what keeps anyone from trying other values there. `isPermittedFrame` is `isGetRequest(payload) || isSetRequest(payload)`. `isGetRequest` is not changed.
