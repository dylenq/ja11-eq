<objective>
First contact with writes on the real JA11, in the order D-17 fixes: backup, preset switch,
identity apply, test curve, restore. Each step is confirmed by read-back, everything is logged,
and the procedure stops at the first unexpected result.

Purpose: this is where the phase goal is actually met - a curve goes into the DAC's USER1 slot
safely, is confirmed, and the original comes back. It is also where the open questions from
STATE.md are answered on the device.

Output: `02-DEVICE-LOG.md` with every command and its output, the device findings of D-19, and the
dongle back in its original state.

How the end of the phase is arranged (D-18): the executor runs all five steps including the
restore, so the plan ends with the dongle restored and the restore itself proven by read-back
before anyone relies on it. The two checks only a person can do - hearing the test curve and
unplugging the dongle - are done afterwards with three commands: apply the test curve, check,
restore. This was chosen over leaving the test curve on the dongle for the human because it keeps
D-17's order intact, never leaves the user's dongle modified while it waits for verification, and
makes the restore command the user runs one that has already worked once.

This plan changes no source file. If the device shows a defect in the code, that is an unexpected
result: stop and report. Fixes come back through planning, not through this plan.
</objective>

Stop rule, valid for every task of this plan (D-17, D-04):

An unexpected result is any of: a `ja11-eq` exit status other than 0; a `result:` line that does
not say confirmed; a `ja11-probe` output that differs from what the step expects; a `ja11-eq` or
`ja11-probe` crash. At the first one: run nothing further that writes. Run `ja11-probe` once to
record the state the dongle is in, append everything to the log, and end the plan with a report
that names the step, shows the output, and gives the user the command that would restore
(`ja11-eq restore`). Do not run that restore yourself after an unexpected result, do not repeat
the failed command, do not change the source and try again, and do not send anything by other
means. A dongle whose slot or values do not change after a SET frame is "the device ignores SET
frames": that is the D-04 stop condition, and the answer is to stop, not to try other bytes.

Two things are not unexpected results: an `info: state not readable in this slot:` line from
`ja11-eq slot` (it answers a D-19 question), and `ja11-probe` - a read-only command - exiting 1
straight after a save while the dongle re-enumerates; run the probe again, up to three times, and
record how long the dongle was away. Log such a probe run with the line `probe-away: 1` in place of
its `exit:` line, so that every `exit:` line in the log belongs to a command that had to succeed.
A probe that still exits 1 on the third try is an unexpected result.
